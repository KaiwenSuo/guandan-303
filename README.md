# 六人掼蛋网页版（红蓝两队，每队3人）

可部署的 Node.js + Socket.IO 实时联机游戏。支持 6 人房间、分享链接、昵称入座、房主开局、手牌私密发送、服务器校验出牌、轮流出牌、过牌、胜负判定、断线重连、再来一局。前端适配手机和电脑。

## 本地运行

需要 Node.js 20 或更新版本。

```bash
npm install
npm start
```

浏览器访问 http://localhost:3000 。同一台电脑开6个无痕/不同浏览器窗口可体验6人联机；正式测试建议6台设备。运行 `npm test` 执行规则单元测试。

## 部署公网（Render 示例）

1. 将项目文件上传到自己的 GitHub 仓库（根目录含 package.json、server.js）。
2. 在 Render 创建 **Web Service** 并连接该仓库。选择 Node 环境，Build Command 设置为 `npm install`，Start Command 设置为 `npm start`。
3. 选择支持 WebSocket 的部署配置；保持 **单实例** 运行。服务上线后访问 Render 提供的 HTTPS 地址。
4. 创建房间，复制 `https://你的域名/?room=房间号` 发送给朋友。对方打开后填写昵称、点击加入。

亦可在 Docker 平台运行：`docker build -t guandan . && docker run -p 3000:3000 guandan`。部署服务必须允许 Socket.IO WebSocket/长轮询连接。免费服务可能休眠，唤醒后房间内存可能丢失。

## 当前玩法（约定版，非官方六人标准）

- 3副标准牌共162张，每人27张，座位1、3、5为红队；2、4、6为蓝队。
- 座位1先出，按座位序轮流出牌；其余未出完牌的玩家都选择不要后，上一手出牌者（如已出完则其下一位未出完玩家）重新领出。
- 支持单张、对子、三张、三带二、5张顺子、三连对、两连三张（钢板）、5张同花顺、同点数4张及以上炸弹、3小王+3大王的六王炸。
- 炸弹大于同花顺，同花顺大于普通牌型，六王炸最大；炸弹先比张数再比点数；普通牌型必须相同才能比较。
- 同队三人全部出完手牌时胜利。已出完牌者跳过出牌顺序。
- **尚未实现** 逢人配、进贡还贡、升级计分、特殊接风规则、机器人托管、观战和语音。请与朋友事先确认采用本约定玩法。

## 运维与安全说明

- 房间状态只存于 Node 进程内存：服务重启后房间丢失；12小时未操作自动清理。请勿水平扩容为多个进程，除非增加 Redis 共享状态与 Socket.IO adapter。
- 断线重连依赖浏览器 localStorage 中的随机凭证，换设备或清除浏览器数据无法找回原座位。
- 玩家断线时当前对局会等待该玩家重连；没有自动托管。
- 房间链接是可分享的私人房间入口，不是密码保护；有链接者可在空座位时加入。
- 无支付、赌博或现金结算功能。

## 303 六人规则扩展（2026-10-28）
- 6人红蓝两队交替座位，3副牌，每人27张。
- 全部六名玩家按出完牌的顺序计名次；第五名出完后自动确定第六名。
- 头游队升级 `max(0, 10 - 三名队员名次之和)`，另一队不升级。
- 第2局起：四游向头游、五游向二游、末游向三游进贡各自最大的非王牌，获贡者回赠一张10及以下非王牌；若贡牌者合计持有3张大王，可由贡牌者提出抗贡。
- 3张大王炸 > 5张炸 > 3张小王炸 > 4张炸；6张及以上炸弹（张数越多越大）> 3张大王炸；6王天王炸最高。5张同花顺介于5张炸和3张大王炸之间。
- 每队独立级牌，红心级牌可作为百搭配牌。
- A级终局目前采用连续三次满足“升级至少一级且无人末游”的保守解释；图片的“三局之内升级”存在歧义，正式使用前建议确认。

### 当前限制
- 服务器房间为内存存储，重启会清除游戏；生产环境建议接入持久化存储。
- 未实现完整赛事级的牌型枚举、复杂配牌优先级、特殊同点炸弹裁定和所有争议边界；需要多人联机验收。
- 抗贡目前由任一贡牌者提出即生效，仍需确认具体抗贡申请机制。
- 进贡回贡在牌不足或缺少合规还贡牌时可能无法推进，正式上线前需增加异常处理。


## V4：A级三局胜负规则（用户确认选项 A）

某队首次升到 A 后，从**下一局**起有三局机会。三局中只要任意一局该队取得头游、按十减法升至少一级，且该队无人末游，即刻赢得整场比赛；不要求连续三局成功。若三局均不符合则本次挑战失败。其他队头游的对局同样计入三局期限。服务端使用 `aWindow` 记录剩余机会，取代 V3 的连续成功计数。
